## Context

当前线上试穿提示已经通过原生多图定义固定模特、待买商品和衣橱来源单品的角色，并以服装图片像素和关键几何结构为最高保真约束。本 change 只替换其摄影风格层，详细动机和范围见 `proposal.md`，行为契约见 `specs/outfit-try-on-styling/spec.md`。

## Goals / Non-Goals

**Goals:**

- 将默认摄影表达固定为经过对照实验验证的 Quiet Luxury 方向。
- 将所有进入生图模型的服装统一建模为强制清单，而不是为外套或其他单一类别添加特例。
- 保持当前生图请求协议、输入顺序、模型自主穿法和服装保真优先级。
- 通过版本号和单元测试让线上新旧 Prompt 可追踪、可回归验证。

**Non-Goals:**

- 不改变决策模型、候选筛选、试穿并发、数据库或前端布局。
- 不把 `summary` 重新作为生图指令，也不新增结构化穿法字段。
- 不为已有历史图片自动重生成。

## Decisions

1. **在现有 Prompt 末尾替换风格层。** 保留公共的身份、服装几何、负向约束和原生多图段落，仅新增一段明确的 Quiet Luxury direction。这样可以将本次变量控制在摄影表达层，避免重新引入已解决的输入角色问题。

2. **在 Prompt 中写入强制服装数量。** Prompt 构建器根据 `closetItemIds` 计算 `1 件待买商品 + N 件衣橱服装`，明确 Image 2 及全部 Image 3+ 都是不可选的必穿项。相比只写“use every garment”，显式数量和图片范围更容易让生图模型建立完整清单。

3. **以类别无关的正确穿着规则覆盖所有服装。** 每件服装必须穿在常规身体位置并保留足够可识别结构；不得拿在手中、搭在肩上、系在腰间、放在背景中或与另一件合并。分层冲突通过敞开外层、调整姿势和构图解决，而不是省略服装。外层敞开只是保障内层可见的一种手段，不是针对外套的孤立特例。

4. **将版本号升级为 `outfit-try-on-v6-quiet-luxury-mandatory-garments`.** 版本号写入后端试穿记录，便于线上对照、历史追踪和回滚识别；旧版本结果不受影响。

5. **只强制服装完整性，不固定具体造型。** 模型仍可以在所有必穿单品清晰可辨的边界内自主决定塞入、垂放、开合和姿势；Quiet Luxury 只约束环境、光线、姿态气质、色彩克制和轮廓层级，不新增鞋包或未提供配饰指令。

6. **负向提示补充通用的错误使用模式。** 继续禁止模特原服装继承、颜色漂移、版型改变、拼板和僵硬证件照，并新增遗漏、完全遮挡、合并、错误身体位置、手持、肩搭、腰系和离身放置等禁止项。

## Risks / Trade-offs

- [高级编辑感可能牺牲日常感] → 保留“自然站姿、可穿、生活方式摄影和真实材质”约束，避免变成秀场或纯画册。
- [复杂分层可能弱化任一输入服装的可见性] → 使用统一的强制清单、件数和正确穿着规则，并让风格、姿势和场景服从全部服装的可识别性。
- [Prompt 约束仍无法形成确定性的视觉证明] → 本次先强化清单、数量和正确穿着定义；如果线上仍出现遗漏，下一步应增加生成后多模态核验与定向重试，而不是继续堆叠单品类别特例。
- [单次供应商延迟有随机波动] → 本次不调整并发或超时配置，使用 Prompt 版本记录后再通过线上样本观察中位耗时。

## Migration Plan

1. 更新 Prompt 构建器的风格层、强制服装清单和版本号。
2. 更新相关测试，验证 Quiet Luxury、强制服装数量、正确穿着和 summary 隔离。
3. 运行 OpenSpec strict validation、相关测试、TypeScript 检查和 ESLint。
4. 部署后新请求使用 v6；历史已完成试穿图继续读取原有记录，不自动迁移或重生成。
