## Why

衣橱页面目前只有关键词搜索，顶部的品类、风格、颜色、季节和状态控件仍是静态占位。随着衣服数量增加，用户需要按多个已识别属性组合定位单品，而不是依赖记住名称或标签文本。

## What Changes

- 将品类、风格、颜色、季节和状态控件变成可交互的多选筛选菜单。
- 从完整衣橱数据生成动态的品类、风格和颜色选项，并提供固定的季节与穿着状态选项。
- 让多个筛选维度之间使用 AND 关系，并与现有关键词搜索共同生效。
- 将状态映射为“常穿、偶尔穿、闲置、待确认”；四季衣服在任意具体季节筛选中都命中。
- 当某个筛选维度存在已选值时，在触发器右侧显示独立的 `X` 清除按钮；点击后只移除该维度条件，不打开菜单或影响其他条件。
- 提供单维度“全部”清除、全部重置、结果数量反馈和无结果恢复操作。
- 保持待确认面板、全量衣橱统计、上传流程、AI 分析、数据库和 API 行为不变。

## Capabilities

### New Capabilities

- `closet-filters`: 在衣橱卡片网格上按多个衣服属性组合筛选。

### Modified Capabilities

- `closet-search`: 关键词搜索与结构化筛选组合时使用交集，并在筛选条件生效时提供统一的结果反馈和重置行为。

## Impact

- 主要影响 `src/app/app/page.tsx` 的衣橱视图和 `src/lib/closet/filter-items.ts` 的纯筛选逻辑。
- 扩展现有筛选单元测试，并进行 lint、生产构建和桌面/移动端 UI 验证。
- 不新增数据库迁移、Supabase 查询、API、第三方依赖或 AI 流程。
- 保留工作区中与本需求无关的用户本地修改。
