## Context

待确认上传卡片目前在图片下方渲染一段识别/展示图说明，再渲染最多八枚由 `image_quality_flags` 派生的标记胶囊。识别队列和处理状态来自本地队列、忙碌集合及质量标记；展示图状态以 `display_image_status` 为单一事实来源。参见 proposal.md 与 `closet-upload-workflow` 规格。

## Goals / Non-Goals

**Goals:**

- 用固定两行表达两个用户可感知的异步任务状态。
- 在进行中提供不干扰图片和表单的小尺寸动态反馈。
- 保留完成、失败和待生成等状态的可读、可访问反馈。

**Non-Goals:**

- 不改变识别、生图、保存、重试或通知的请求时序与状态写入。
- 不改变已保存衣橱卡片的标签摘要或质量标记的数据本身。
- 不为待确认卡片新增展示图重试入口。

## Decisions

### 使用 `thinking-orbs` 的 20px 行内组件

使用 MIT 许可的 `thinking-orbs` 20px 预设分别表达识别和展示图的进行中状态。该组件以 Canvas 渲染、内建离屏暂停与减少动态效果支持，适合在两行小尺寸状态中使用；完成、失败和待生成状态使用现有 Lucide 静态图标，避免不必要的持续动画。

替代方案是以 CSS spinner 实现。该方案无需依赖，但不能满足用户指定参考组件的动效语言，因此不采用。

### 以现有状态源派生两条独立进度

识别行按本地队列、处理中、失败、持久化排队标记和完成状态派生，并包含刷新后仍存在的 `closet_analysis_queued` 标记；若该历史标记与 `ai_label_ready` 同时存在，则成功标记优先，避免误报。展示图行只从 `display_image_status` 派生。全局加载状态只继续保护交互，不参与单件衣服的进度文案。这样保留现有异步分支的数据所有权，不新增状态字段。

### 以单一礼貌状态区域承载两行文案

两行被包裹在一个 `role=status`、`aria-live=polite` 区域中；动态球标记为装饰性，避免其 canvas 标签与可见文本重复播报。文字始终存在，因此减少动态效果、完成、失败和待生成状态都不依赖颜色或动画传达含义。

## Risks / Trade-offs

- [第三方组件增加少量客户端资源] → 使用该包的 20px 预设，并仅在待确认卡片的进行中行渲染。
- [刷新后本地队列信息丢失] → 同时读取持久化的识别排队标记，避免把排队任务误报为已完成。
- [大量待确认卡片同时更新可能产生多次状态播报] → 每张卡只使用一个礼貌状态区域，且仅在状态变化时由浏览器播报。

## Migration Plan

1. 安装依赖并替换待确认卡片的图片下方状态区。
2. 通过静态检查、生产构建和桌面/移动端视觉验收确认两行布局与异步状态切换。
3. 如需回滚，移除新组件和依赖即可恢复既有进度区域；不涉及数据迁移。
