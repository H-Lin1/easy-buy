## Context

见 `proposal.md` 的 Why。当前 `ClosetCard` 在标题下始终显示 `category`，再使用可换行的标签胶囊展示最多七个风格和场景标签。卡片图片已是正方形，冗长的文字区会明显拉长卡片并造成不同单品高度不一致。

## Goals / Non-Goals

**Goals:**

- 将已保存卡的非图片信息压缩为标题与单行标签摘要。
- 在不占用常规卡片高度的情况下提供所有标签。
- 同时支持鼠标悬浮、键盘焦点和触屏点击。

**Non-Goals:**

- 不改变待确认卡及其可编辑字段。
- 不变更标签的存储、排序、筛选、搜索或 AI 识别结果。
- 不将品类从数据或筛选条件中移除，只停止在已保存卡中重复展示。

## Decisions

### 1. 固定显示前四个去重后的标签

卡片按当前视觉优先级先使用风格标签、再使用场景标签，保持原顺序并去除重复值。前四个标签构成摘要，其余数量显示为 `+N`。四个标签在当前三到四列桌面网格与两列平板网格中可读，同时避免多行。

不改为只显示两个标签，因为会隐藏过多用户已确认的风格信息；也不把所有标签压成纯文本，因为胶囊可快速区分元信息与标题。

### 2. `+N` 使用 hover/focus 预览与显式展开

`+N` 是具有 `aria-expanded` 的按钮。桌面端悬浮或焦点出现绝对定位的完整标签浮层，常规卡片高度不变；点击或键盘触发则切换内联完整标签区，满足触屏与可发现性需求。鼠标离开只关闭预览，不取消用户显式展开的内容。

摘要前四个标签不在浮层或展开区中重复渲染；两种查看方式只使用摘要之后的剩余标签。这让 `+N` 的数量、内容和卡片新增高度保持一致。

摘要、浮层预览和内联展开共用相同的胶囊基础样式，包括高度、字号、内边距、背景色与文字色。摘要仅额外应用均分可用宽度和截断；剩余标签按内容宽度呈现，但不缩小视觉规格。

不只用 CSS hover，因为触屏与键盘用户无法访问；不使用全局 tooltip 库，避免为单一卡片交互增加依赖。

### 3. 状态继续留在图片区

穿着状态维持现有图片右上角角标。卡片标题只显示名称，删除下方 `category` 文本；品类仍是数据、筛选和确认表单的一部分。

## Risks / Trade-offs

- [标签文本很长仍可能挤压摘要] → 摘要容器不换行并允许截断，完整名称始终在浮层或展开区可读。
- [浮层被相邻卡片或滚动容器遮挡] → 浮层使用卡片内较高层级并保留点击展开的替代入口。
- [同一标签同时出现在风格与场景中] → 在摘要与完整列表中去重，避免重复占位。

## Migration Plan

1. 部署纯客户端展示调整，无数据迁移。
2. 使用四个及五个以上标签的卡片分别验证摘要、悬浮、焦点、点击和移动端展开。
3. 如需回滚，恢复独立品类行及多行标签胶囊；标签数据不受影响。
