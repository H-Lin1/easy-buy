## Context

当前决策清单已读取 `decision_items`，而聊天完成态已将报告、方案和真人搭配结果持久化在关联会话中。该变更只在客户端把已有数据整合为紧凑的复盘视图；详情见 proposal.md 与本变更规格。

## Goals / Non-Goals

**Goals:**
- 在不改变既有 AI、数据库写入和认证流的前提下，查询并复用决策会话的最后报告与真人图。
- 让一条卡片保持两列结构，左列较原方案放大约三分之一以展示完整商品图，并将完整分析入口置于价格下方；宽右列优先展示 1:1 真人穿搭图。
- 在移动端退化为垂直布局，同时保留方案内容的可读性。

**Non-Goals:**
- 不为历史记录重新生成真人图。
- 不改变决策的保存、购买状态或聊天页的生成流程。
- 不在清单中重放 AI 长篇结论或恢复颜色、尺码编辑。

## Decisions

- 从关联聊天会话中提取已保存报告和 `tryOnBatch`，而不是新增数据库字段或 API。这样复用已有的一对一方案与真人图关系，避免数据迁移；替代方案是写入冗余快照，但会增加保存路径与一致性风险。
- 将每个方案的界面状态局限在清单组件内，按决策 ID 保存当前选择。这样方案切换不会影响聊天状态；替代方案是全局单一选中方案，会导致浏览多条记录时相互干扰。
- 右列使用“1:1 真人图 + 来源单品”并排结构；桌面端来源单品列填满真人图高度，首项贴顶、末项贴底，其余项目均分中间空白。这样待买单品加一件裤装时裤装能与真人图底部对齐，三件或更多时仍保持均衡节奏；小屏时改回普通纵向间距。
- 图片使用白底容器和 `object-contain`。相比裁切式 `cover`，这是保存待买商品完整视觉信息所必需的。
- 详情入口位于左列价格下方，并通过现有会话选择逻辑打开聊天页，而非新增路由，保留当前会话恢复与加载行为。

## Risks / Trade-offs

- [旧消息缺少或格式异常的报告数据] → 仅渲染可读取的单品与文字，并显示无真人图提示。
- [加载关联会话会增加清单初始请求量] → 仅查询清单记录关联的必要消息字段，并对缺失结果降级。
- [真人图片 URL 失效] → 使用聊天页一致的图片加载失败提示，不影响来源单品和说明阅读。

## Migration Plan

1. 部署前不需要数据迁移，因为界面读取已有的持久化会话结果。
2. 发布后，新旧决策均可浏览；旧决策自然使用降级状态。
3. 如需回滚，仅回退前端清单展示代码，不会留下额外数据或后台任务。
