## Context

见 `proposal.md` 的 Why。待确认界面的收起与延后功能由页面级临时状态控制，待确认卡的重新识别还包含局部反馈表单；移除这些入口后，对应状态和回调链可以一起删除。季节字段则横跨 AI 提示与解析、确认 API、Supabase 数组、客户端与服务端映射、筛选、搜索、embedding 文本和搭配评分，当前英文值已经成为事实上的内部协议。

## Goals / Non-Goals

**Goals:**

- 让待确认区域只呈现确认所需的信息和命令。
- 保持“全部确认”仍只处理高置信度项目，避免文案缩短扩大操作范围。
- 建立单一的季节中文规范化入口，并让所有读写路径消费同一组值。
- 以可检查、幂等的迁移更新已有季节数组。

**Non-Goals:**

- 不移除已保存衣橱卡的重新识别标签和重新生成展示图能力。
- 不改变 AI 高置信度阈值、确认向量生成、图片异步分支或上传进度。
- 不重做待确认表单布局，也不新增季节控件库。

## Decisions

### 1. 删除待确认专属的隐藏、延后与重新识别状态链

页面不再维护待确认面板整体隐藏状态和单件延后 ID 集合，`ClosetView`、`ClosetConfirmationPanel` 与 `ClosetConfirmationCard` 同步移除相应 props。待确认卡局部的重新识别开关、反馈文字和入口一并删除，但页面现有重新识别执行函数继续供已保存衣橱卡使用。

这比只隐藏按钮更合适，因为不可达状态会增加后续维护成本；同时保留底层重新识别能力，避免影响用户已验收的已保存卡工作流。

### 2. “全部确认”只更改文案，不更改目标集合

批量按钮继续使用现有高置信度与识别成功筛选条件，并沿用忙碌态判断。文案缩短为“全部确认”代表“确认当前可安全批量确认的全部项目”，不将低置信度或识别失败记录纳入请求。

标题使用一个 `h3` 文本节点承载完整文案。桌面端尽量与按钮同排，窄屏允许自然换行或换行布局，但不拆回说明段落。

### 3. 季节规范值由共享模块统一定义

新增无运行时依赖的季节模块，导出五个中文规范值、筛选选项以及单值/数组规范化函数。映射覆盖英文大小写、`fall`、连字符/空格变体和常见中文别名，输出保持首次出现顺序并去重；不受支持的值不进入规范数组。

AI 提示直接要求中文值，解析层仍调用规范化函数防御供应商偏离。客户端和服务端读取同样规范化，以兼容迁移尚未应用或缓存仍含旧值的短暂窗口。确认 API 在构建 embedding 文本和数据库更新之前规范化，保证新写入不会恢复英文值。

不只在 UI 翻译英文标签，因为那会继续让数据库、筛选和检索依赖两套语义；也不只依赖提示词，因为模型输出不能视为强约束。

### 4. 固定季节筛选直接使用中文值

季节筛选的 `value` 与 `label` 使用相同中文规范值；“四季”继续作为具体季节的通配标签，选择“四季”时不反向匹配具体季节。搜索自然匹配用户看到的中文季节词，搭配评分中的季节集合也同步改为中文。

### 5. 数据迁移先校验再转换

新增 Supabase SQL migration。迁移先枚举所有现有季节数组元素并检查是否可映射；如存在未覆盖值则中止并列出异常值，避免静默丢失数据。通过检查后，迁移按原数组顺序映射并去重，重复执行结果保持不变。

数据库迁移负责结构化 `season` 数组。既有 embedding 向量不在 SQL 中重算，避免在 schema migration 中引入外部 AI 调用；结构化筛选和搭配评分会立即使用中文值，用户后续确认时 embedding 文本和向量按中文季节重新生成。

### 6. 穿着频率弱化样式由选择框显式启用

通用选择框增加可选的 pending 值样式参数，仅穿着频率传入 `unknown`。这样“待确认”显示为中性灰色，而版型的 `unknown` 保持现状，避免全局改变通用控件。

### 7. 识别期间由进度状态统一控制 AI 字段占位

待确认卡以 `analysisProgress.state === "in_progress"` 作为唯一判断。识别排队或进行中时，名称继续展示上传文件名，穿着频率继续展示可选择的灰色“待确认”；品类、颜色、版型、风格标签、场景标签和季节标签统一展示灰色“待识别”，并暂时禁用这些 AI 字段，避免用户输入在识别结果返回时被覆盖。

占位仅用于界面呈现，不写入确认草稿或数据库。识别结果返回后，卡片按现有结果更新机制重新渲染，所有 AI 字段同时恢复实际值和常规文字颜色。这样不会把示例 placeholder 误认为已识别内容，也不会引入一组新的持久化状态。

### 8. 删除优先于识别与生图任务

待确认卡的删除按钮只受本条删除请求约束，不受识别、展示图或上传批次 busy 状态约束。用户确认删除后，客户端立即隐藏记录，将 ID 标记为已删除，移出尚未启动的识别队列，并中止该 ID 已发出的识别与生图请求；所有异步完成分支、图片加载通知和状态合并在回写前检查删除标记，避免迟到结果重新出现。

数据库删除使用 `delete(...).select(...)` 取得删除瞬间的最新图片路径，再清理原图、处理中间图和展示图，以覆盖展示图刚好在删除前提交的竞态。展示图 Route 在上传文件后若无法再提交到对应记录，必须删除刚上传的文件，避免记录已删除时留下孤立对象。若数据库删除失败，客户端取消删除标记并恢复原卡片，允许用户重试。

## Risks / Trade-offs

- [历史数据包含未覆盖的季节自由文本] → 迁移在写入前报出具体异常值，先扩展映射后再执行，不静默删除。
- [AI 仍偶发返回英文或非规范值] → 提示词与解析规范化双重约束，未知值保持为空等待确认。
- [“全部确认”被理解为包含低置信度项目] → 保持既有禁用和目标筛选逻辑，并在成功反馈中继续说明实际确认件数。
- [移除延后后待确认区域持续可见] → 这是本轮聚焦确认动作的预期行为，项目只有确认或删除后才离开面板。
- [旧 embedding 向量仍反映迁移前季节词] → 不阻塞结构化季节功能；后续用户确认会自然重建，若需要全量重嵌入应单独规划后台任务。
- [识别期间编辑 AI 字段会被结果覆盖] → 进行中统一禁用这些字段，只保留名称和穿着频率可操作；结果返回后自动恢复。
- [删除与生图提交同时发生] → 数据库删除返回最新路径，生图失去记录所有权时清理新文件，两侧共同覆盖竞态。
- [取消请求后迟到响应仍返回] → 客户端以删除 ID 集合作为最终门禁，忽略所有迟到回写和通知。

## Migration Plan

1. 先部署共享规范化与兼容读取，使新旧季节值均能安全显示为中文。
2. 执行 SQL migration，确认不存在未覆盖值并转换已有 `season` 数组。
3. 验证数据库中季节 distinct 值只包含五个中文规范值。
4. 部署 UI 精简与中文 AI/确认写入路径；回滚代码时中文值仍可由兼容规范化读取。
