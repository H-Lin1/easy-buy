## Context

参见 `proposal.md`。认证后的产品界面集中在单个客户端页面组件中，空状态、对话状态、分析状态和报告状态共享同一份 `DecisionChatState`。现有 `Composer` 已包含文字输入、截图上传、拖拽和提交能力，因此本次变更应复用它并保持既有请求与保存流程不变。

## Goals / Non-Goals

**Goals:**

- 用明确的状态分支将“准备输入”和“已开始分析”分开渲染。
- 复用现有输入能力，为启动状态提供更聚焦的视觉变体。
- 将启动状态收敛为主副文案和一个输入工具，去除装饰图标与任务指南。
- 为启动输入框提供无额外轮廓的聚焦样式。
- 将提交后的用户内容改为无头像的紧凑图片与主题色文字气泡，并保持分析状态为线性内容流。
- 通过本地计时和逐阶段揭示提供可理解的分析反馈。
- 在桌面和移动端维持稳定、无重叠的布局。

**Non-Goals:**

- 不拆分 `src/app/app/page.tsx` 的整体模块结构。
- 不改变购买分析请求、Supabase 会话、报告数据结构或决策按钮。
- 不引入新的设计系统、动画库或外部依赖。

## Decisions

### 使用显式空状态派生值控制主区域

通过当前对话状态派生 `isConversationEmpty`，仅在没有已提交消息、报告、分析、错误和通知时渲染启动区。草稿文字和待上传截图不应结束空状态，因为它们尚未形成一次提交。

备选方案是让页面始终渲染完整聊天结构，再用 CSS 隐藏部分元素。该方案会保留多余布局节点，且更容易在后续状态组合中出现重复输入区，因此不采用。

### 复用 Composer 并增加 starter 变体

启动区和对话底部使用同一个 `Composer`，通过 `variant` 和可覆盖的 `placeholder` 调整容器间距、输入高度和阴影。这样上传、拖拽、清除图片和提交行为只有一套实现。

备选方案是创建独立的启动输入组件。它会复制文件输入和拖拽状态处理，并增加两个输入组件行为漂移的风险，因此不采用。

### 移除快捷指南并使用精确文案

启动状态不再提供预设任务入口，只保留用户明确要求的主文案、副文案和输入提示。副文案使用不换行样式，并在窄屏使用固定的小字号确保内容仍处于可用宽度内。

### Starter 输入框覆盖全局聚焦轮廓

项目的全局表单聚焦规则为输入控件增加轮廓。Starter 变体在 textarea 上显式关闭 border、outline 和 ring，只保留外层 composer 容器作为视觉边界；对话中的普通 Composer 不受影响。

### 保持提交后界面和数据流不变

提交后继续使用现有 `handleSubmit`、分析进度和 `DecisionReportCard`。本次变更只改变提交前渲染，不触碰 API payload、认证令牌、会话创建或报告保存。

### 使用本地状态驱动顺序进度与计时

提交时记录 `Date.now()` 并将进度重置到第一阶段。现有定时器继续推动阶段索引，但渲染时只展示索引以内的阶段；索引之前的阶段仅显示文字，当前索引使用 `ThinkingOrb`。不同阶段使用 `searching`、`connecting`、`weaving`、`solving`、`composing` 和 `working` 状态，复用已有依赖。

报告成功返回时计算秒级耗时、将步骤视为全部完成并默认折叠。耗时按钮只控制步骤区域的展开状态，不影响报告或数据请求。计时信息仅用于当前页面会话，不写入数据库。

### 准备阶段不渲染报告占位卡

`DecisionReportCard` 只在真实报告存在时渲染。分析期间由进度流承担反馈职责，避免同时出现进度和大型虚线占位框。错误与通知仍使用既有提示区域。

### 用户消息使用紧凑图片与主题色文字气泡

有截图时使用右对齐、等比缩放的图片按钮，将原 420px 最大宽度缩小至 140px，文字位于图片下方并使用现有暖色主题的浅粉底色气泡；无截图时只显示右对齐的同款文字气泡。图片仍保留点击查看大图能力，不改变上传数据或预览弹窗。

## Risks / Trade-offs

- [同一组件内条件渲染块变大] → 保持改动局限在 `ChatView`，并通过静态检查和桌面/移动端验证控制风险。
- [草稿截图参与旧的 `hasUserTurn` 计算] → 空状态判定独立使用“已提交消息”而非截图草稿，提交后仍沿用旧逻辑展示用户消息。
- [单行副文案在窄屏空间有限] → 在移动端使用固定的较小字号，不使用随视口连续缩放的字体。
- [前端阶段定时不代表服务端真实节点完成时间] → 文案表达为用户可见的分析进展，最终仅将总耗时标记为真实请求耗时，不对单阶段耗时作承诺。
- [历史报告没有当前请求的本地计时] → 仅在当前页面完成的请求展示可折叠耗时；历史报告直接展示报告内容。

## Migration Plan

无需数据迁移。部署后新对话直接使用新的启动状态；已有对话和报告继续进入原有界面。回滚时只需恢复本次客户端渲染改动，不影响已保存数据。
